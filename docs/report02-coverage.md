# Repository coverage against report02.pdf

**Historical baseline before implementation.** See [current coverage](report02-current-coverage.md) for the deployed state.

Reviewed: 2026-11-08. Source: [project report](../report02.pdf), all 18 pages, including visual inspection of the design diagrams. Page numbers below match the PDF pages.

The repository implements many components of the proposed MLOps system, but does not yet implement the complete automatic training, monitoring, and deployment loop described in the report. It is a customer-churn classification implementation with a fixed input schema.

**Covered** means the implementation or configuration exists for that capability; it does not mean a live deployment was verified. **Partial** means some implementation exists but a required capability or connection is missing. **Missing** means no implementation was found. **Unverified** means the claim needs runtime or operational evidence.

The most important gaps to close before describing this as the report's complete automated system are: connect Optuna and multi-model selection to training; package preprocessing with the served model; connect drift results to retraining; reload serving after promotion; and implement production-quality metrics from actual outcomes. The report and repository must also agree on MySQL, external data ingestion, dataset uploads, and missing-value handling.

The repository additionally contains MLflow/MinIO integration, GitHub Actions CI/CD, Kubernetes deployment/autoscaling templates, Prometheus-format API metrics, and optional Slack notification helpers. These add implementation detail beyond the report's named stack; they do not resolve the missing connections above. See [.github/workflows](../.github/workflows/), [k8s](../k8s/), and [alerting.py](../src/monitoring/alerting.py).

Real-time streaming is described as a future enhancement on page 17, so it is not counted as a missing current requirement. The report uses “self-training” to describe automated retraining; it does not explicitly require semi-supervised pseudo-labeling.

Validation scope: static inspection of report, source, configuration, workflow calls, and selected test fixtures. No application code changed. No tests, live services, training jobs, deployment, performance benchmarks, or security penetration tests were run. In particular, serving tests mock the model, so their existence does not establish compatibility between a real trained artifact and the API.
