The core automated churn lifecycle is running. The report's broader distributed-processing and continuous-availability claims are not fully satisfied by this single-VM deployment. [Validation evidence](validation.md) separates measured results from remaining limitations; [operations](azure-operations.md) explains access, recovery and costs.

For a real application, first collect representative labeled data, define minimum precision/recall and acceptable error costs, and validate on an untouched time-based benchmark. Start a separate application database for real data so the demonstration's synthetic rows are not mixed into training. Then choose capacity and availability targets; move application data to Azure Database for MySQL and metadata to Azure Database for PostgreSQL, run serving across multiple hosts (or Azure Container Apps), and use Azure ML compute if training outgrows this VM. GitHub OIDC deployment is configured; use the manual workflow on `main` for future releases.
